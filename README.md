# ⚛️ LibLabTab — интерактивная физика

Каталог интерактивных физических симуляций, которые работают прямо в браузере — без установки, плагинов и сложной математики на старте. Тяните магнит, крутите маятник, собирайте электрическую цепь, меняйте параметры и наблюдайте за законами природы в реальном времени. Каждая модель сопровождается теорией, вопросами для самопроверки с ответами под спойлером и таблицей контрольных точек.

🌐 **Сайт:** [liblabtab.ru](https://liblabtab.ru) · 📄 **Лицензия:** MIT

## 🚀 Особенности

- **Мгновенная загрузка.** Статическая генерация: страницы собираются один раз и отдаются как обычный HTML. Шрифты локальные, без обращений к Google Fonts. Обложки — векторные SVG, встроенные прямо в разметку каталога.
- **Настоящая физика, а не анимация.** Конструктор цепи решает систему методом узловых потенциалов с Ньютоном для диодов и неявным Эйлером для C и L. Численные результаты сверены с аналитикой: RC и RL дают ошибку около 1 мВ на шаг, резонанс RLC — амплитуду 0,98 А против теоретических 1,0 А.
- **Честные границы моделей.** В описаниях прямо сказано, что упрощено: парность взаимодействия, сферическая аппроксимация молекул, кусочная модель транзистора, отсутствие пробоя диода.
- **SEO и шеринг.** Автоматические `sitemap-index.xml`, `rss.xml`, `robots.txt`, Open Graph. На сайте обложки в SVG, для соцсетей — одноимённые PNG 1200×630.
- **Даты без сдвигов.** Даты публикаций хранятся как момент UTC и форматируются строго в UTC, поэтому не съезжают на день у посетителей в других часовых поясах. Время внутри дня задаёт порядок вывода.
- **Самопроверка моделей.** Часть симуляций содержит встроенный самотест (Бернулли, бильярд Пенроуза). На странице модели кнопка «Проверить модель» запускает его прямо в iframe и показывает таблицу «модель / эталон / итог».
- **Комментарии на своём хостинге.** Лента под каждой моделью: ответы, лайки, удаление своих сообщений, защита от спама. Работает на PHP и SQLite, данные остаются в России и не зависят от сторонних сервисов.
- **Публикация.** `deploy.bat` собирает сайт и синхронизирует папку сборки с хостингом через WinSCP, не трогая базу комментариев. Полный цикл с проверками и Git — `node tools/release.mjs`.

## 🛠 Стек

- [Astro](https://astro.build/) — фреймворк и статическая сборка
- TypeScript — типизация контента и схем коллекций
- Markdown + frontmatter — описания моделей
- Vanilla JS + HTML5 Canvas — симуляции, без внешних зависимостей
- SVG / PNG — обложки и иконки
- PHP 7.4+ и SQLite (`pdo_sqlite`) — комментарии, один файл `public/api/comments.php`
- WinSCP + FTP — публикация
- Хостинг: Reg.ru (Россия), домен `liblabtab.ru`

## 💻 Локальный запуск

Требуется Node.js 22+.

```bash
npm install
npm run dev
```

Откройте [http://localhost:4321](http://localhost:4321). Изменения подхватываются автоматически.

Сборка в папку `dist`:

```bash
npm run build
```

## ✅ Проверка симуляций

Перед публикацией:

```bash
node tools/check.mjs          # статическая проверка симуляций
npx astro check               # типы и схема контента (0 errors)
npm run build                 # сборка в dist
node tools/smoke.mjs          # браузерный смоук-тест на 360 px (нужен npm run dev в другом окне)
node tools/smoke.mjs --wide   # то же на 1280 px
```

Смоук-тест использует Playwright: один раз выполните `npx playwright install chromium`. Он открывает каждую симуляцию и ищет ошибки консоли, пустую сцену, горизонтальную прокрутку, неработающий ползунок, отсутствие кнопки «Сброс» и значения `NaN` в показаниях.

Если на машине нет Playwright, достаточно первых трёх команд.

## 📦 Публикация

```bash
deploy.bat
```

Скрипт запускает `npm run build`, затем через WinSCP выполняет `synchronize remote -delete -mirror` — сервер становится точным зеркалом папки `dist`. Всё, чего нет в сборке, с сервера удаляется, поэтому вручную положенные файлы в корне сайта держать нельзя: кладите их в `public/`.

Единственное исключение — база комментариев `api/data/comments.sqlite`: она создаётся на сервере, и команда синхронизации обязана её пропускать (`-filemask="|api/data/; *.sqlite"`). Без этого каждая выкладка стирает все комментарии.

Полный цикл (проверки, коммит, push, выкладка):

```bash
node tools/release.mjs "Сообщение коммита" --deploy
node tools/release.mjs --dry     # только показать план
node tools/release.mjs "…" --fast   # без astro check и сборки
```

Скрипт не делает `force push` и не сливает чужие коммиты молча: при отклонённом push он подсказывает `git pull --rebase origin main`.

FTP-пароль в `deploy.bat` не хранится: он читается из переменной окружения `LLT_FTP_PASS` (один раз: `setx LLT_FTP_PASS "пароль"` и перезапуск терминала). Файлы `deploy.bat`, `deploy.log`, `tree.txt` и архивы сборки исключены из Git.

## ➕ Как добавить модель

1. **Симуляция.** HTML в `public/sim/`, например `ohm.html`. Шрифты подключайте локально: `<link rel="stylesheet" href="/fonts/fonts.css">`. Полезно добавить `<link rel="canonical" href="https://liblabtab.ru/models/имя/">`, чтобы полноэкранный режим не считался дублем страницы модели.
2. **Обложки.** В `public/covers/` два файла с одинаковым именем: `имя.svg` для карточки и `имя.png` 1200×630 для соцсетей. PNG удобно получить через `tools/cover-export.html`.
3. **Описание.** `src/content/models/имя.md`:
   ```yaml
   ---
   title: "Название модели"
   date: 2026-11-15T19:00:00Z
   description: "Короткое описание для карточки и поисковиков."
   section: "электричество"      # раздел: одно значение из SECTIONS в content.config.ts
   level: "базовый"              # базовый | продвинутый
   grade: "10-11"                # 7-9 | 10-11 | вуз (необязательно)
   tags: ["постоянный-ток", "школьный-курс"]   # только свойства из TAGS
   model: "имя.html"
   cover: "/covers/имя.svg"
   order: 14                     # положительное целое; при равных датах побеждает больший
   coreVersion: "1"
   draft: false
   answers:                      # необязательно: ответы на вопросы самопроверки
     - q: "Текст вопроса из раздела «Вопросы для самопроверки»"
       a: "Ответ"
   checkpoints:                  # необязательно: контрольные точки
     - name: "Что проверяем"
       setup: "Настройки"
       expected: "Ожидаемое значение"
   ---
   ```
   Дата — момент UTC. Модель с датой в будущем в каталог не попадает, пока сайт не пересоберут после этого момента (сайт статический). Время внутри дня определяет порядок в каталоге. Раздел задаётся полем `section`, а не тегом. Допустимые значения тегов перечислены в `src/content.config.ts`: схема отклонит неизвестный тег на этапе `astro check`.
4. **Проверка.** `npm run dev` → откройте `/models/имя/` и поработайте с моделью.
5. **Проверка.** `node tools/check.mjs`, `npx astro check`, `npm run build`, при желании `node tools/smoke.mjs`.
6. **Публикация и история.** `node tools/release.mjs "Модель: название" --deploy`, затем `Ctrl + F5` на сайте.

## 🗑 Как удалить модель

Удалить четыре файла (`src/content/models/имя.md`, `public/sim/имя.html`, `public/covers/имя.svg`, `public/covers/имя.png`), проверить поиском по проекту остальные упоминания, при необходимости добавить `Redirect 301` в `public/.htaccess`, собрать и запустить `deploy.bat`. Каталог, sitemap, RSS и страницы тегов перестроятся сами.

## 💬 Комментарии

Компонент `src/components/Comments.astro` подключён на странице каждой модели.

- **Боевой сайт:** запросы идут на `/api/comments.php`. Скрипт сам создаёт папку `api/data/` и базу SQLite, закрывает папку через `.htaccess`.
- **`localhost`:** комментарии хранятся в браузере, PHP для разработки не нужен.
- **Защита:** скрытое поле-ловушка, не чаще одного сообщения в 20 секунд и 30 в час с одного адреса, не более двух ссылок в тексте, проверка `Origin`, один лайк на адрес. IP хранится только в виде хэша.
- **Удаление своего комментария:** по секретному токену, который хранится только в браузере автора.

**Требования хостинга:** PHP 7.4+ с расширениями `pdo_sqlite` и `mbstring`. Проверка: `https://liblabtab.ru/api/comments.php?page=/test` должен вернуть `[]`, а `/api/data/comments.sqlite` — 403 или 404.

**Модерация.** Скачайте `api/data/comments.sqlite` по FTP, откройте в DB Browser for SQLite и поставьте `approved = 0` у нужной строки. Для предмодерации замените `DEFAULT 1` на `DEFAULT 0` в схеме внутри `comments.php` и удалите старый файл базы.

**Резервная копия.** Раз в месяц скачивайте `api/data/comments.sqlite` в папку вне репозитория. В Git база не попадает: `public/api/data/` указан в `.gitignore`.

## 🔒 Безопасность и данные

- Секреты (FTP-пароль и т. п.) не хранятся в репозитории; если пароль когда-либо попадал в файл под контролем версий, его нужно сменить.
- Заголовки безопасности и кэш заданы в `public/.htaccess`.
- Для комментариев собираются имя (вводит сам посетитель), текст, время и хэш IP. Укажите это в политике конфиденциальности сайта (`/privacy/`).
